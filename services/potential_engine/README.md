# SPAT grounding potential engine

See [BACKLOG.md](BACKLOG.md) for model extensions, validation work, and run-mode recommendations.

This C++17 command-line service solves the quasi-static potential distribution generated by a network of straight, buried, cylindrical electrodes in a homogeneous, two-layer or n-layer (up to 8 layers) horizontally stratified, isotropic soil. It uses the point-source Green function ρ/(4πr) with an image for the insulating air/soil boundary (homogeneous), the Sunde/Tagg image series truncated with an a-priori bound of 1e-7 (two layers, `two-layer` soil line), or the n-layer kernel described below (`n-layer` soil line), a piecewise-constant leakage-current basis, a Galerkin (length-averaged) method of moments with the thin-wire reduced kernel, the line integral of each source segment in closed form, 8-point Gauss-Legendre quadrature over the target graded towards near sources, LU with partial pivoting through 1,500 segments, and row-equilibrated GMRES from 1,501 through 4,000 segments. Both paths use the same dense interaction matrix. Conductors with the same `group` are treated as electrically bonded and equipotential. Separate groups interact through the soil and can be driven by independent current injections; groups without injected current are floating conductors with zero net current.

Supported segment `kind` labels include `grid`, `rod`, `bond`, `fence`, `cable_shield`, `structure`, or application-defined tokens. The label is preserved by the caller; electrically, all segments are ideal conductors with the supplied radius. Each physical electrode must be divided into straight segments. Use negative `z` for buried depth and `z=0` for grade; query points use `z >= 0`. Coordinates and radii are in metres, soil resistivity in ohm-metres, current in amperes, and outputs are volts/ohms.

## Build

From the repository root run `make potential-engine`. The API Docker image compiles the same C++ source and sets `SPAT_POTENTIAL_ENGINE=/usr/local/bin/spat-potential-engine`.

## Python pipe client

```python
from src.infrastructure.calculations.potential_engine_client import (
    ElectrodeSegment,
    PotentialEngineClient,
    PotentialPoint,
    rectangular_grid_segments,
    rectangular_surface_points,
    potential_difference_v,
    touch_voltage_v,
)

engine = PotentialEngineClient()  # Uses subprocess.Popen with stdin/stdout pipes.
mesh = rectangular_grid_segments(
    length_m=10, width_m=8, conductor_spacing_m=2, burial_depth_m=0.5,
    conductor_radius_m=0.006, rods_count=4, rod_length_m=2.4,
    discretization_m=2,
)
mesh.append(ElectrodeSegment("fence_leg", "fence", "fence", (7, 0, -0.2), (7, 8, -0.2), 0.005))
result = engine.calculate(
    soil_resistivity_ohm_m=100,
    segments=mesh,
    injections_a={"grid": 1000},
    injection_origins={"grid": "fault:bus-1"},
    points=rectangular_surface_points(x_min_m=-2, x_max_m=12, y_min_m=-2,
                                      y_max_m=10, spacing_m=1),
)
result["diagnostics"]  # backward error, condition/pivot estimates (-1 under GMRES), iterations, current balance
result["trace"]        # protocol, solver version, method, assumptions, units, hashes, segments, injections
step_voltage_v = potential_difference_v(result, "surface_0_0", "surface_1_0")
touch_voltage_v_at_point = touch_voltage_v(result, "grid", "surface_5_5")
```

Alternatively, run the executable directly and write the versioned whitespace protocol to stdin. A request starts with `SPAT-POTENTIAL-3`, then a soil line `homogeneous <rho> <segments> [quadrature_tolerance]`, `two-layer <rho_upper> <rho_lower> <upper_thickness> <segments> [quadrature_tolerance]` or, since solver 3.2.0, `n-layer <count> <rho_1> <thickness_1> ... <rho_count> inf <kernel_density> <segments> [quadrature_tolerance]` (layers from the surface down; `inf` only and always for the bottom half-space; `kernel_density` 6–12 fitted images per decade, 10 by default; the quadrature tolerance defaults to 1e-9 and accepts 1e-12–1e-4); segments may not cross an interface (the Python client splits them), one segment row (`id group kind x1 y1 z1 x2 y2 z2 radius`) per segment, injection count and rows (`group current_a origin`), point count and rows (`id x y z`), and `END`. Output is tab-separated: `META` rows (protocol, solver version, method, assumptions, units, counts), `DIAG` rows (`backward_error`, `condition_1norm_estimate`, `pivot_ratio`, `solver_iterations`, `max_relative_balance_error`, `quadrature_tolerance`, `quadrature_evaluations`, `quadrature_refinements`, `quadrature_max_depth`, `quadrature_interactions`, `quadrature_max_evaluations_per_interaction`, `quadrature_converged`, `interaction_degenerate_pairs`, `interaction_self_pairs`, `interaction_shared_endpoint_pairs`, `interaction_t_junction_pairs`, `interaction_crossing_pairs`, `interaction_near_pairs`, `interaction_separated_pairs`, `interaction_near_interface_pairs`, `matrix_reciprocal_entries_reused`; for homogeneous and two-layer soil `image_terms` and `image_series_tail_bound`; for n-layer soil `kernel_density`, `kernel_terms`, `kernel_functions`, `kernel_images_per_pair_max`, `kernel_lambda_samples`, `kernel_spectral_evaluations`, `kernel_image_depth_min_m`, `kernel_image_depth_max_m`, `kernel_error_bound`, `kernel_max_amplification`, `matrix_image_work` and `point_image_work`), optional `WARNING` rows, `SEGMENT id current_a`, `GROUP id injected_a potential_v resistance_ohm|null origin balance_error_a potential_spread_v`, `POINT id potential_v`, then `END`. GMRES reports -1 for the condition estimate and pivot ratio because LU-based estimates are unavailable; an `iterative-solver` warning makes this explicit. Errors are a single `SPAT-POTENTIAL-3\tERROR\t...` row with exit status 2.

### Explicit electrical topology (solver 3.5.0)

Requests without connections keep the `SPAT-POTENTIAL-3` contract. When `connections` are supplied, the Python client sends `SPAT-POTENTIAL-4`: after injection rows, provide `BOND <count>` and rows `<id> <group_a> <group_b>`, then `RESISTOR <count>` and rows `<id> <group_a> <group_b> <resistance_ohm>`, before the point count. Group connectivity is explicit; geometry does not infer a bond. An ideal bond contracts its two equipotential groups into one electrical node. A resistor contributes a conductance-Laplacian term between two group nodes. `CONNECTION <id> <current_a>` reports resistor current with positive direction from `group_a` to `group_b`; ideal bond current is not reported because its split is not unique in this formulation. Group potentials are shared across a bond, while each original group remains in the response. Per-group current balance is the residual for the connected electrical node.

This topology model treats each group as an equipotential node and supports ideal unions and lumped resistances between groups. A conductor's longitudinal resistance can be approximated by assigning each discretized electrical cell its own group and joining adjacent cells with resistors sized for their lengths and material. The solver does not derive those cells or resistances from artifact geometry yet; that conversion and artifact connectivity remain follow-up work. The solver keeps separate conductor groups unless the request explicitly bonds or connects them.

### Multiple excitation scenarios (solver 3.6.0)

`PotentialEngineClient.calculate_scenarios(...)` sends `SPAT-POTENTIAL-5`, with the same soil, segment geometry, connections and observation points for all cases. After the `BOND` and `RESISTOR` sections, `SCENARIOS <count>` is followed by one `SCENARIO <id> <injection_count>` header and its signed `<group> <current_a> <origin>` rows per case. Each result block begins `SCENARIO <id>`, contains the normal metadata, diagnostics, segment/group/connection/point rows, and ends `END_SCENARIO`; the whole response ends `END`. Every excitation has independent potentials, leakage currents, link currents, KCL balance and backward residual. The client returns a dictionary keyed by scenario ID.

For direct systems, matrix assembly and LU factorization are shared across all scenarios; each RHS is solved with the same LU factors. Above the direct solver's segment limit, the engine assembles the matrix once and runs GMRES separately for each RHS because this path has no reusable LU factorization. The factorization timing is reported once in every block and the iteration count is per scenario.

### Contract of the n-layer extension (solver 3.2.0)

The protocol header stays `SPAT-POTENTIAL-3`: the `n-layer` soil line is an explicit, additive extension, and homogeneous and two-layer requests and responses are unchanged (an older binary answers an `n-layer` line with a `soil line must be ...` error). An n-layer response adds `META soil_model n-layer`, `soil_layer_count`, `soil_layers_resistivity_ohm_m_thickness_m` (the request, `rho:thickness;...;rho:inf`), `soil_solved_layers` (after merging adjacent layers of exactly equal resistivity, with an `equal-layers` warning; a stack that merges into one layer is solved by the homogeneous path) and `kernel_limits`, plus the `DIAG kernel_*` rows above. In Python, `LayerStackSoil(((rho, thickness), ..., (rho, None)), kernel_density=10)` serialises to this line, `soil_record` records it in the trace, `interface_depths`/`split_at_interface` cut segments at every interface (parts `<id>.L<k>`, two-layer parts keep `.u`/`.l`), `kernel_terms`/`image_work` mirror the engine's cost estimate exactly, `point_batch_size` splits rasters to respect it, and the client refuses a response that did not solve `n-layer`. N-layer query points must lie on the surface (`z = 0`).

### N-layer kernel

For a point current in layer *i* observed in layer *j* the Hankel-transformed potential is the direct term plus four terms `c_pq(λ) exp(-λ(σ_p + τ_q + δ_pq))`, where σ and τ are the distances of source and observation to the top/bottom of their layers and δ the thickness the direct ray crosses (factored out analytically). The bounded coefficients `c_pq` come from the stable generalized reflection/transmission recursion of a static layered medium (local reflection `K_k = (ρ_k − ρ_{k−1})/(ρ_k + ρ_{k−1})`, +1 at the insulating surface; Sunde 1949, Koefoed 1979, Chew 1990 §2.1); every factor is a Möbius map of `exp(−2λh)` with modulus ≤ 1, so nothing overflows and the bottom half-space simply has no reflected upgoing wave. Each `c_pq − c_pq(∞)` is approximated by real exponentials on a fixed geometric grid of image depths (truncated-SVD least squares, the real-image variant of the complex-image method of Chow et al. 1992 and Li et al. 2006); every exponential is an exact image, i.e. a mirrored or translated copy of the source segment, so the analytic line integral, graded Galerkin quadrature and far-image Gauss rule of the two-layer path apply unchanged. Segments lying on an interface belong to the layer below; their nearest images are handled by the same near-singular quadrature. The full formulation and references are in `src/main.cpp` ("N-layer soil").

Error control is a-posteriori and reported per request: the residual of every fitted function is evaluated on a lambda grid 2–4 times denser than the fit and, with `|J0(x)| ≤ min(1, √(2/(πx)))` (Watson §13.74), integrated into a bound of the spatial error relative to the direct coupling `min(ρ_i, ρ_j)/R` at every distance up to the problem extent (`kernel_error_bound`). The bound is conservative: in the tests the actual differences are 10–100 times smaller.

| N-layer limit | Value | Reason |
|---|---|---|
| Layers | 1–8, bottom one a half-space | agreed scope; 9 or more and a finite bottom layer are refused |
| Layer thickness | 0.01–1000 m | as the two-layer path |
| Resistivity | (0, 1e6] Ω·m; max/min of the stack ≤ 1e4 | beyond 1e4 the fit loses accuracy (bound ~1e-2 at 1e5) |
| Fitted images per coefficient | ≤ 120 (`kernel_density` × decades + 1) | refuses stacks whose total depth / thinnest layer / contrast need more |
| Kernel error bound | refused above 1e-4, warning above 1e-5 | e.g. density 6 on a 300/60/1000 Ω·m stack is refused |
| Coefficient amplification Σ\|a\|/max\|f\| | ≤ 1e6 | cancellation guard; measured ≤ 40 |
| Spectral evaluations | ≤ 1e6 | at most 64 layer pairs × 4 functions × ~1500 samples |
| Image evaluations | 4e9 matrix and 4e9 points, as two layers | same cost model; mirrored by `image_work`, rasters batched by `point_batch_size` |
| Client timeout / memory | 60 s / 512 MiB | unchanged: kernel setup is < 0.1 s and the matrix is the same size |

## Calculations from design artifacts

The API queues a calculation for an immutable artifact version (`POST /api/v1/projects/{project_id}/artefactos-diseno-tierras/{artifact_id}/versions/{version}/calculos-potencial`). The Celery task `spat.calculate_artifact_potential` runs the engine and stores the result and the full trace in `calculos_potencial_tierras`. Artifact soil layers (top to bottom, `depth_m` = thickness, `null` for the bottom half-space) become homogeneous soil (one layer after merging adjacent layers of exactly equal resistivity), the two-layer image series (two layers) or the n-layer kernel (3–8 layers); a finite bottom layer, a missing thickness, more than 8 layers or a stack outside the kernel limits, and grids above the 4,000-segment limit, are rejected with an explanation. `POST .../artefactos-diseno-tierras/mediciones-suelo/ajustar` with `layer_count` 3–8 fits a Wenner/Schlumberger sounding with `calculations/n_layer_soil.py` (Koefoed transform, real-image forward model, leave-one-out outlier exclusion, per-parameter uncertainty, engine-compatible bounds); its `soil_layers` can be stored in an artifact and calculated as they are. See `backend/src/infrastructure/calculations/artifact_potential.py` and BACKLOG.md.

## Acceptance checks and limits

The engine rejects a result whose normwise backward error exceeds 1e-10, whose 1-norm condition estimate exceeds 1e13 (warning above 1e10), whose per-group current balance error exceeds 1e-9 of the total injection, or that contains non-finite values. Before solving, both the Python client and the engine reject duplicate IDs or geometry, overlapping collinear segments, segments of different groups that touch or cross (bond them in one group instead), segments lying on the surface, segments shorter than 5 radii, radii outside 0.1 mm–0.5 m, coordinates beyond 100 km or depths beyond 1 km, resistivity outside (0, 1e6] Ω·m, currents above 1 MA, and points below grade.

| Limit | Value | Basis |
|---|---|---|
| Segments per request | 4000 | Grid 5 at 1,883 segments, GMRES 55 iterations, 1.87 s, 1.1e-15 backward error; 2,079 segments in 2.29 s. LU and GMRES agree exactly for resistance and GPR at 1,883. See `validation/benchmark-grid5-large-macos-arm64.json`. Re-measure on deployment CPU. |
| Points per request | 100 000 | |
| Points × segments | 2e7 | 480 × 40 000 in 0.9 s; larger rasters must be split into batches |
| Image evaluations (two layers) | 4e9 for the matrix and 4e9 for the points | worst allowed case 5.7 s with K = −0.5 and 12.3 s with K = 0.82 (Linux image); `point_batch_size` splits rasters accordingly |
| Image-series terms | 2000 | above that the engine refuses the soil contrast instead of truncating silently |
| Client timeout | 60 s | about 50 times the worst measured case; re-measure on the deployment CPU |
| Client address-space limit | 512 MiB (Linux only) | about 10 times the measured peak |

The interaction matrix is dense, so assembly and storage grow quadratically with segment count; LU solve time grows cubically. GMRES avoids the cubic factorization but still uses dense matrix-vector products, and its 1-norm condition estimate is unavailable (reported as -1 with a warning). The 4,000-segment cap keeps the matrix within the worker memory budget; this is not yet a path to 10,000+ segment designs. Re-run the benchmark on the target hardware before raising any limit or allowing synchronous API calls.

### Phase profiling

Run `make potential-engine-profile` to profile homogeneous, two-layer, four-layer and eight-layer soils over 10, 20 and 40 m meshes. It prints per-phase timings and writes complete input/output traces to `/tmp/grounding-potential-engine-profile.json`. Override the trace path with `PROFILE_OUT=/path/to/profile.json`; pass `ARGS='--meshes 20:5,60:5 --points 400'` to change the workload. Each response reports kernel setup, matrix assembly, LU factorization, solve, condition estimate, point evaluation, total engine time and peak resident memory. The profile is for local investigation; rerun it on deployment hardware before changing limits.

## Validation

`validation/reference_cases.json` holds the reference cases with geometry, inputs, reference values, tolerances and the source, method and edition of each reference. They cover a single rod, a horizontal wire, bonded rods, separately driven coupled rods and a floating rod (Dwight closed forms, IEEE Std 142), and IEEE Std 80-2013 Annex H Grids 1–2 and Annex B Example 1 (published CDEGS/ETAP/WinIGS and EPRI results). `tests/infrastructure/test_potential_engine.py` runs every case. `validation/convergence.py` reports the relative change of resistance, GPR, touch and step voltages as segments and surface rasters are refined.

Prefer graded segmentation (`Segmentation`/`discretize`; default for artifact calculations), which reaches the converged corner step voltage with 40–55 % fewer segments (`validation/segmentation_study.py`); `estimate_uncertainty` reports a Richardson error estimate per quantity. With uniform segments use at most 1 m, or less near rods and grid corners: at 2.5 m the corner step voltage of a rodded grid is still about 5 % off its converged value. `validation/REVIEW.md` (regenerate with `validation/review_report.py`) is the package for the reviewer. Tolerances and the transcribed published values are pending sign-off by an independent, competent grounding engineer. Check each value against a licensed copy of the cited standard.

Two-layer validation adds IEEE 80 Annex H Grids 3–6 and Annex B Exhibit 1: 38 of 42 checks pass; the four known deviations (Grid 4 fence-only resistance and Exhibit 1) are documented with their investigation in the cases and in `REVIEW.md`.

N-layer validation (`tests/infrastructure/test_n_layer_engine.py`, `test_n_layer_soil.py`): an independent reference (`tests/infrastructure/layered_green_reference.py`: full boundary-condition system per wavenumber and numerical Hankel integration) matches the surface potential of a source in every layer of 3-, 4- and 8-layer stacks and the coupling between layers within 2e-5; the 2-layer kernel reproduces the image-series route within 1e-6 (resistance) and 2e-5 (every check of Annex H Grids 3 and 6 and Annex B Exhibit 1); reciprocity holds to 1e-7, the potential is continuous across every interface, and refining the kernel converges. The sounding model reproduces the published USGS OFR 80-190 three-layer curves within 0.85 % and the OFR 81-160 four-layer curve within 4 % (both computed with Ghosh's short 1971 filter; direct quadrature confirms our values to 1e-4). `validation/n_layer_benchmark.py` measures time against mesh size, points and layer count (`validation/benchmark-n-layer-macos-arm64.json`).

Version 1 of the engine used ρ/(2πr) for a buried source and overestimated every resistance and voltage by a factor of about two. Treat any result produced with `SPAT-POTENTIAL-1` as invalid.

## Scope

The element kind is descriptive; dimensions and radius shape each electrode's soil coupling, and electrical bonds are represented by a shared group. The solver assumes ideal equipotential metal and a total current injection per group. It solves homogeneous, two-layer and 3–8-layer horizontally stratified soil (n-layer query points on the surface only); it does not solve laterally heterogeneous soil, contrasts above 1e4, finite conductivity/inductance inside metal, frequency-dependent complex impedance, transient lightning, or a surface layer in the field. Current division (`fault_current.py`) and IEEE 80 tolerable limits (`safety_criteria.py`) are applied by the backend around the engine, not inside it. Results are computational estimates that require engineering validation and comparison with site measurements and a qualified design tool before safety decisions.
